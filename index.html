1. 项目定位与核心原则

目标：做厦门（含鼓浪屿）本地深度的 AI 旅行智能体。不做全球一句话订行程的复制品，做地头库存 + 真实导游经验的不可替代层。

核心护城河：931 栋历史建筑档案、烟火气小吃与古早味踩点数据、不在 OTA 上架的好店与靠谱关系。

原则：

  • 自建库优先，外部 MCP（高德、抖音本地生活、携程/飞猪）只做兜底，不得覆盖本地判断。
  • 酒店下单走「意向单 + 人工确认」，不做实时扣库存裸奔平台。
  • Spec 先行，一切给 Bot / Cursor 的输入必须可执行、可验收。
  • 内部关门测试阶段先跑通，不上线不办 ICP / 算法备案。

2. 整体架构画面（Harness）

想象一个旅行社前台：

  • Router（接待员）：无状态。只看哪个窗口空，把会话（session ID）扔过去。不办业务。
  • Worker（窗口）：完整 LangGraph 实例。每个窗口后面是一套相同的工作站（图 + 节点 + 插件）。会话状态全在 Redis，窗口之间不共享私货。
  • 主循环子图：模型节点（Qwen 选工具）→ 工具执行节点（跑插件）→ 结果回填节点。循环直到模型说「答完了」。
  • 插件工具箱（六个核心）：酒店查询、餐厅查询、行程生成（harness 函数）、高德 MCP、微信 MCP、支付宝 MCP。
  • 记忆检索插件：统一入口，按场景路由到不同语义库。
  • 监控：每个节点挂 OTel span，旁路记录，不干预。

LangGraph 是骨架，dsh「一切皆插件」是血肉。工具、循环子图、检索入口都可插拔替换，主图不动。

3. 六层详细 Spec

3.1 模型层

主模型 Qwen3.8 Omni Flash Realtime
语音 + function calling 一体，中文方言（含闽南语）覆盖最好，数据在北京/新加坡，成本极低。
  • 备份语音通道：MOSS TTS + 转写（moss-tts / moss-transcribe）
  • 图片理解重任务：Nex N2.6（异步子 agent）
  • 视频实时：MOSS-VL-Realtime（第三期，走云 API，不本地 4090）
  • 备选：GPT Realtime / Gemini Live（仅客户明确要求或主模型挂掉时切换，需重过合规）

3.2 工具层

  • 酒店查询：自建轻量系统（约 20 家合作酒店结构化卡片）。下单生成意向单，人工确认后回传。不对接 PMS。
  • 餐厅查询：双库。自建踩点库优先（小吃、老字号、烟火气），外部联网兜底。
  • 行程生成：不是独立工具，是 harness 内函数。输入模板 + 槽位约束 + 实时库存，输出标准 JSON 行程。
  • 无机票/动车工具，游客自订。
  • 支付：微信 MCP + 支付宝 MCP，密钥与风控交给通道方。
  • 高德 MCP 接入（POI、地理编码、路径规划）。美团外卖不接。
  • 查询优先级写死：自建库 > 外部 MCP。

3.3 编排层（Harness）

  • 选型：LangGraph + LangSmith（开发期免费层）。
  • 插件规范：每个工具独立文件，声明名称、JSON Schema、超时、降级返回值、监控指标。
  • 循环子图可替换。
  • 超时 3 秒，重试一次，再失败降级并打标（partial / no_exact_match）。
  • 状态全进 Redis，TTL 30 分钟。
  • 并发三档触发：日活会话 800 → 第二档；8000 → 第三档。Worker 水平扩展，无状态。

3.4 记忆层

基于 CoALA 框架 + LangGraph checkpointer / store + dsh 挂载思想。

  • 五个独立语义库（共享 HNSW 向量基础设施）：
    1. 931 栋历史建筑档案库
    2. 小吃探店 / 烟火气库
    3. 文化典故 / 讲解库
    4. 打卡点库
    5. 古早味库
  • 统一检索插件：规划场景打规划库，讲解场景打讲解库，可并行。
  • 混合检索：HNSW 向量 + BM25 关键词 + 结构化字段过滤，RRF 融合。
  • 规划库维度参考：位置、性价比、评分、设施、服务、餐饮、房间、实时库存、团购价、实拍、资质、用户历史偏好、上下文（时间地点天气）、转化导向等。
  • 讲解库维度：故事密度、文化代表性、在地人认同度、拍照出片度、适老适亲。
  • 数据偏差处理：原档案高置信度优先；用户贡献作为旁注，标注「未经核实」。

3.5 视觉层

两套方案：

  • 行前（还没到厦门）：Odessia 式生成式 UI。PC 为主，agent 按需组装地图、房型图、价格表、多版本行程对比。
  • 行中（已在鼓浪屿 / 三丘田）：动态层 + 增强层。
    • 动态层：高德 MCP 真实路网折线 + Leaflet / 高德 JS API 渲染，实时算路、标点、语音讲解。GPS + CLIP 融合定位（先粗定位缩小候选，再照片精匹配）。
    • 增强层：仅对 931 栋中最有故事的约 50 栋做轻量空间锚点，输出结构化数据让雷鸟 / Rokid 等眼镜 SDK 自己渲染。你控制「看见什么」，不控制「怎么看见」。不做全岛 3D 预建模。
    • 打卡点作为独立图层叠加在路网上。

3.6 监控层

  • OTel span 挂在每个节点（进图、出图、工具调用、LLM 调用）。
  • 开发期：LangSmith 免费层（每月 5000 条 base trace）。
  • 准生产后：可升级团队版 + 部分 OTel + 自托管 LangFuse 尝鲜。
  • 最优终态：自托管 LangFuse，数据不出内网；敏感路径（支付、下单、前端展示）人工确认，后台逻辑可静默合并。
  • Engine（自动诊断开 PR）成本较高，准生产阶段再考虑。

4. 三套成本方案

阶段触发条件主要配置月成本量级
低成本 MVP内部测试 / 月活 < 200全走 Qwen + MOSS 云 API，LangSmith 免费层，Redis 小实例，无本地 GPU几百元
准生产月活 ≥ 200 + 首个付费客户LangSmith 团队版，OTel 半接入，Redis 队列削峰，LangFuse 单机尝鲜数千元
最优自愈月活 ≥ 800 + 有真实故障模式自托管 LangFuse，完整 OTel，企业级模型并发折扣，敏感路径人工闸门按量 + 企业折扣

前期一个人完全可承受。视频模型从第一天规划走云 API，不买 4090 当生产。

5. 合规清单（内部测试阶段可暂缓）

  • ICP 备案：对外提供网站/小程序服务时必须。内部测试不对外可先不做。
  • 算法备案：生成合成类算法需在「互联网新技术新应用信息服务备案系统」（beian.cac.gov.cn）填报。自提供服务之日起 10 个工作日内。纯内部关门测试可暂缓。
  • 大模型登记：仅调用 API、未微调/蒸馏，走登记（比备案轻）。
  • 拟人化交互合规（《人工智能拟人化互动服务管理暂行办法》）：高危操作人工确认、日志留痕。
  • 生成合成内容标识：可见 + 隐式标识。
  • 等保三级：对外上线时建议提前启动。

当前策略：先关门自己测试跑通三个核心工具 + 语音，真要放给游客用时再排期备案。

6. Inventory as a Service 商业层（独立于六层）

更高维度：把厦门地头库存、931 栋档案、实时价格做成开放 API 层。任何模型、任何眼镜、任何 App 都能调。你不跟消费者抢关系，当基础设施收抽成。

  • 控制「看见什么」，不控制「怎么看见」。
  • 输出结构化空间数据（锚点坐标、POI 标签、实时状态）给各家 SDK 渲染。
  • 收入模型：预订佣金 + 私人定制介绍佣金 + 未来可能的 API 调用抽成。

7. 开发顺序与下一步

  1. 起 LangGraph 骨架 + Redis 会话。
  2. 接入 Qwen Realtime + 三个核心工具插件（酒店、餐厅、行程生成）。
  3. 跑通最小语音对话：问需求 → 查库 → 出行程 JSON。
  4. 加高德 MCP 兜底。
  5. 补记忆库（先做 100 栋最有故事的 + 一批踩点餐厅）。
  6. 行前生成式 UI + 行中动态地图。
  7. 监控埋点与降级逻辑完善。

验收关键指标（MVP）：语音首包 < 800ms，端到端 P95 < 2s，工具调用成功率 ≥ 99%，降级率 < 5%。
