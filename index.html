1. 项目定位与非目标

目标：厦门本地深度 AI 旅行智能体（行程规划 + 智能讲解）。

非目标（明确不做）：

  • 不做全球一句话订机票酒店。
  • 不对接酒店 PMS 实时扣库存。
  • 不做原生 App（仅 PC 网页 + 微信小程序）。
  • 不做全岛 3D 预建模。
  • 不强制用户授权邮箱或微信聊天记录。
  • 不在运行时自动修改知识库（必须人工审核）。

2. 整体架构

Router-Worker + 规划子图 + 讲解子图 + 反馈离线 Agent。LangGraph 骨架 + 插件化。

3. 失败模式目录（每个组件四种返回）

组件正常超时空结果非法输入
酒店查询房型列表缓存价 + partial最近 3 家 + no_exact_match错误码 + 提示
餐厅查询自建库结果外部兜底隐藏点建议驳回
高德 MCP路径折线重试 1 次后降级空路径坐标错误
规划子图2-3 套 JSON降级为简单模板提示补充偏好槽位不全
讲解子图语音 + 图片缓存讲解「暂无档案」定位失败

所有失败必须打标签并记入 OTel span。

4. 任务依赖图与审查优先级

  1. P0 亲自审：LangGraph 骨架 + Redis 会话（依赖：无）
  2. P0 亲自审：Qwen Realtime 接入 + 规划子图最小闭环（依赖：骨架）
  3. P1 自检 + 抽查：酒店/餐厅插件 + 硬信息校验节点（依赖：规划子图）
  4. P1 自检 + 抽查：讲解子图旁路触发（依赖：骨架）
  5. P2 自检：反馈收集 Agent + 离线管道（依赖：记忆库）
  6. P2 自检：视觉层 + 监控埋点（依赖：上述全部）

并行任务不超过 2 个，审查带宽优先保证 P0。

5. 双向追溯

每条 Spec 条目 ↔ 任务 ID ↔ 代码 PR / Commit。

  • Spec 中每个章节标注对应任务号。
  • 任务描述必须引用 Spec 原文条目。
  • 出现 bug 时，从 trace 定位到具体 Spec 条目，5 分钟内可追溯。

6. Eval 集与成本模型

Eval 集（一等公民）

  • 回归集：真实生产 trace，人工标准答。
  • 合成集：按模板生成，覆盖 931 栋 + 小吃。
  • 对抗集：模糊问题、错误 GPS、时间冲突。
  • 一致性 eval：同一问题多会话对比。

成本模型（月估算）

  • Qwen Realtime：按音频 token 计，目标 < 800ms 首包。
  • 高德 MCP：按调用次数。
  • LangSmith：免费层 5000 trace/月。
  • Redis：小实例免费试用。
  • 目标：MVP 阶段月成本 < 500 元。

7. 六层 + 反馈 + 防幻觉（继承 v1.3）

反馈收集 Agent、防幻觉四机制、视频教训落地全部保留。硬信息校验、多方案输出、置信度标记为必须项。

8. 开发顺序

  1. LangGraph 骨架 + Redis（P0）
  2. Qwen + 规划子图最小闭环（P0）
  3. 酒店/餐厅插件 + 硬信息校验（P1）
  4. 讲解子图（P1）
  5. 反馈 Agent + 记忆库（P2）
  6. 视觉层 + 监控（P2）

验收：语音首包 <800ms，P95 <2s，工具成功率 ≥99%，硬信息校验覆盖率 100%。
